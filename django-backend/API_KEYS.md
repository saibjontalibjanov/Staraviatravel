# API keys and environment settings

Store real values only in **`django-backend/.env`**, alongside `manage.py`. Never paste secret values into this README, browser JavaScript, screenshots, Git commits, or public `VITE_*` settings. The tracked `.env.example` contains names and safe local defaults only.

Create the file once:

```sh
python scripts/setup_env.py
```

To import compatible provider settings from an existing Strapi `.env` instead:

```sh
python scripts/setup_env.py --from-strapi /absolute/path/to/old/.env
```

The script refuses to overwrite an existing `.env`. It copies provider values privately, generates a new Django signing secret, and does not reuse old Strapi JWT/signing keys. Edit the generated file locally, then restart Django and the Telegram worker. Rebuild the frontend if `VITE_API_URL` changes.

| Setting | What to put here |
| --- | --- |
| `DJANGO_SECRET_KEY` | Long random Django signing secret. Generated by setup; required. |
| `DJANGO_DEBUG` | `True` for local development; **`False` in production**. |
| `DJANGO_ALLOWED_HOSTS` | Comma-separated hostnames, without scheme, such as `your-domain.com,api.your-domain.com`. |
| `DJANGO_HTTPS_ONLY` | `False` locally; `True` in HTTPS production. |
| `TRUST_PROXY_HTTPS` | Enable only behind a trusted reverse proxy that overwrites `X-Forwarded-Proto`. |
| `TRUST_PROXY_CLIENT_IP` | Enable only behind a trusted proxy that overwrites `X-Real-IP`; otherwise rate limits use the direct peer IP. |
| `DATABASE_URL` | Empty for `data/db.sqlite3`; PostgreSQL URL for production. Do not commit database passwords. |
| `PUBLIC_WEBSITE_URL` | Website origin used in client links, for example `https://your-domain.com`. No `/checkout` path. Local: `http://localhost:3000`. |
| `PUBLIC_BACKEND_URL` | Public HTTPS Django origin used for Telegram webhook and CRM links. This replaces `PUBLIC_STRAPI_URL`. |
| `CLIENT_ORIGINS` | Exact permitted website origins for public cross-origin API requests. |
| `CSRF_TRUSTED_ORIGINS` | Exact trusted origins for the staff workspace when a proxy is used, including `https://`. |
| `VITE_API_URL` | Optional **public** API origin compiled into the frontend. Leave empty for same-origin hosting. Never put a secret here. |
| `SERPAPI_KEY` | SerpAPI Google Flights key. Without it, ticket searches return a configuration error instead of invented fares. |
| `TELEGRAM_BOT_TOKEN` | BotFather bot token. Server/worker only. |
| `TELEGRAM_LEADS_CHAT_ID` | Numeric target chat/group ID for new lead notifications; groups often start with `-100`. |
| `TELEGRAM_WEBHOOK_SECRET` | Random 16–256 character letters/digits/underscore/hyphen secret for webhook verification. |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Docker Compose PostgreSQL settings. Set a strong URL-safe password; do not leave it empty. |
| `CLICK_SERVICE_ID`, `CLICK_MERCHANT_ID`, `CLICK_SECRET_KEY` | Reserved placeholders, **not an active payment integration**. A Service ID alone cannot confirm real payments. |

Required HTTPS endpoints for provider access: outgoing `serpapi.com` and `api.telegram.org`; incoming Telegram requests at `/api/telegram/webhook`. Only click **Connect webhook** after the backend is publicly reachable over HTTPS. A bot can have one registered webhook at a time.

Production example (placeholders, not working credentials):

```dotenv
DJANGO_DEBUG=False
DJANGO_HTTPS_ONLY=True
DJANGO_ALLOWED_HOSTS=your-domain.com
PUBLIC_WEBSITE_URL=https://your-domain.com
PUBLIC_BACKEND_URL=https://your-domain.com
CLIENT_ORIGINS=https://your-domain.com
CSRF_TRUSTED_ORIGINS=https://your-domain.com
VITE_API_URL=
```

Preserve the generated `DJANGO_SECRET_KEY` and fill actual provider values privately. In the CRM, Integrations reports only whether keys are configured; it never reveals their values.
